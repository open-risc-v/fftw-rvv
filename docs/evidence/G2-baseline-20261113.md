## 为什么用发布包而不是 git 树

FFTW 的 git 仓库不带 `n1_2.c` 这类 codelet：它们由 `genfft`（OCaml）从 `.mc` 生成，且生成规则
只在 `--enable-maintainer-mode` 下存在。容器里要额外装 OCaml、再开 maintainer 模式，才能编出
和发布包一样的库——成本高于收益。发布包自带预生成 codelet，用 sha256 固定同样可复现。

## 两个坑

1. **`makeinfo` 不存在**：发布包默认要构建 info 手册，容器无 texinfo 时 `fftw3.info` 目标直接
   失败。用 `make MAKEINFO=true` 跳过文档，不影响库。
2. **探针不要 include `<complex.h>`**：一旦引入，`fftw_complex` 会按 C99 复数类型解析，
   `out[k][0]` 这种下标写法立刻编译不过。FFTW 的数组写法只用 `fftw3.h` 就够。
